# netspeed

Замер скорости скачивания: делает N последовательных запросов к одному адресу,
считает среднее время запроса, объём скачанных данных и скорость.

Зависимостей нет — только стандартная библиотека Python 3.10+.

## Запуск

```bash
python3 netspeed.py <адрес> [-n 10] [-t 30]
```

Пример:

```bash
python3 netspeed.py "https://speed.cloudflare.com/__down?bytes=5000000" -n 10
```

Параметры:

| Флаг | Смысл | По умолчанию |
|---|---|---|
| `-n`, `--requests` | сколько запросов сделать | 10 |
| `-t`, `--timeout` | таймаут одного запроса, секунды | 30 |
| `--allow-cache` | не обходить кэш | обходим |
| `--close-connection` | закрывать соединение после каждого запроса | переиспользуем |
| `--json` | вывод в JSON для машинной обработки | текстовый отчёт |

Код возврата: `0` — хотя бы один запрос прошёл, `1` — все упали.

## Принятые решения и почему

Задача выглядит простой — цикл, замер времени, деление. Но в таком виде
скрипт выдаёт правдоподобный и при этом неверный результат. Три места,
где это происходит:

**Кэш.** Со второго запроса файл отдаётся из кэша браузера, прокси или CDN,
и скорость получается фантастической. Поэтому к адресу добавляется уникальный
параметр `_cb=<uuid>` и отправляются заголовки `Cache-Control: no-cache`
и `Pragma: no-cache`. Отключается флагом `--allow-cache`, если нужно замерить
именно работу кэша.

**Сжатие.** Если сервер отдаёт gzip, прочитанный объём не равен размеру файла,
и скорость завышается. Запрос идёт с `Accept-Encoding: identity`.

**Что считать временем.** В полное время запроса входят DNS, установка TCP
и TLS-рукопожатие — в примере выше это 550 мс из 2,5 секунд. Если делить
объём на полное время, получится не пропускная способность канала,
а смешанная величина. Поэтому замер разделён:

* **скорость передачи** — объём делится на время чтения тела ответа.
  Это и есть пропускная способность.
* **скорость с учётом соединения** — объём делится на полное время запроса.
  Это то, что чувствует пользователь.

В отчёте выводятся оба числа, потому что по отдельности каждое вводит
в заблуждение.

**Медиана рядом со средним.** Одна просадка канала сдвигает среднее,
а медиану почти нет. Расхождение между ними само по себе признак
нестабильного соединения.

**Мбит/с и МиБ/с.** В задании написано «мб/с», а это двусмысленно: разница
между мегабитом и мегабайтом — восемь раз. Выводятся оба значения с явной
подписью; провайдерские мегабиты считаются в десятичной системе (10⁶),
двоичные мегабайты — в 2²⁰.

**Соединение переиспользуется** (`Connection: keep-alive`), поэтому TLS-рукопожатие
происходит один раз, а не десять. Это ближе к реальному скачиванию.
Флаг `--close-connection` переключает на новое соединение каждый раз —
тогда видно цену установки соединения.

## Проверки согласованности

Скрипт не только считает, но и сообщает, когда замеру нельзя верить:

* объём ответа менялся между запросами — адрес отдаёт разный контент;
* `Content-Length` не совпал с фактически прочитанным;
* файл меньше 512 КБ — на таком объёме замер определяется задержкой,
  а не пропускной способностью (нужен файл от 5 МБ);
* разброс скорости больше трёх раз — либо канал нестабилен,
  либо часть ответов пришла из кэша.

Смысл в том, что отчёт без таких проверок выглядит достоверным при любом
из перечисленных случаев.

## Ошибки

Сбой одного запроса не прекращает замер: строка помечается как ошибка,
статистика считается по успешным, в итоге видно «успешно / всего».
Обрабатываются отдельно HTTP-ошибки, сетевые сбои, таймауты и ошибки TLS —
в отчёте пишется причина, а не «что-то пошло не так».

## Тесты

```bash
python3 -m unittest test_netspeed -v
```

16 тестов, сети не требуют: расчётная часть и проверки согласованности
вынесены в чистые функции. Проверяются в том числе арифметика скорости,
устойчивость медианы к выбросу, деление на ноль при нулевом времени передачи
и то, что обход кэша даёт разные адреса при повторных вызовах.

## Что сознательно не делалось

* **Параллельные запросы.** В задании сказано «последовательно», и это
  правильнее для замера: параллельные потоки соревнуются за канал
  и показывают другую величину.
* **Замер отдачи (upload).** В задании только скачивание.
* **Сохранение файла на диск.** Тело читается блоками по 64 КБ и отбрасывается —
  замеряется сеть, а не скорость записи на диск.
* **Прогревочный запрос.** Первый запрос не отбрасывается: цена установки
  соединения видна отдельной колонкой, и её лучше показать, чем спрятать.
